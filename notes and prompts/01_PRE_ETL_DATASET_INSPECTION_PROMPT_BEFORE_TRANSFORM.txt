============================================================

First, inspect and identify:

============================================================
2. INITIAL DATA INSPECTION
============================================================

Perform a complete initial inspection of the dataset.

Check:

- DataFrame shape
- Column names
- Data types
- Sample records
- First and last records where useful
- General structure
- Obvious formatting problems

Identify any immediately visible issues.

============================================================
3. DATA PROFILING
============================================================

Perform appropriate profiling for the dataset.

Check for:

- Missing values
- Null values
- Empty strings
- Whitespace-only values
- Duplicate rows
- Duplicate identifiers
- Unique value counts
- Unexpected values
- Inconsistent values
- Value distributions
- Minimum and maximum values where applicable
- Date ranges where applicable

Do not rely only on summary statistics.

Inspect the actual values when necessary.

============================================================
4. COLUMN-BY-COLUMN ANALYSIS
============================================================

Review EVERY column individually.

For each column, determine:

- Column name
- Current datatype
- Actual values and patterns
- Missing value situation
- Formatting consistency
- Whether the values appear valid
- Whether cleaning is required
- Whether transformation is required
- Whether a decision is required before changing anything

Do not assume that a column is clean simply because it has no missing values.

============================================================
5. CHECK FOR COMMON DATA QUALITY ISSUES
============================================================

Thoroughly check for:

TEXT ISSUES:
- Leading whitespace
- Trailing whitespace
- Multiple unnecessary spaces
- Empty strings
- Whitespace-only values
- Inconsistent capitalization
- Inconsistent spelling
- Inconsistent naming
- Special or hidden characters
- Unexpected text values

IDENTIFIER ISSUES:
- Duplicate IDs
- Missing IDs
- Inconsistent ID formatting
- IDs incorrectly converted to numbers
- Leading zeros that must be preserved

NUMERIC ISSUES:
- Incorrect datatype
- Mixed numeric and text values
- Negative values where they may not be valid
- Impossible values
- Suspicious outliers
- Unexpected decimal formatting

BOOLEAN / STATUS ISSUES:
- Multiple representations of the same value

For example:

Yes / YES / yes / Y / True / 1

or:

No / NO / no / N / False / 0

Do not standardize automatically unless the correct business meaning is clear.

DATE ISSUES:
- Incorrect date datatype
- Mixed date formats
- Invalid dates
- Missing dates
- Unexpected future dates
- Suspicious historical dates
- Incorrect relationships between dates

CATEGORY / STATUS ISSUES:
- Inconsistent category names
- Misspellings
- Different capitalization
- Duplicate categories with different formatting
- Unexpected categories
- Values that may require business decisions

============================================================
6. INDEPENDENT ANALYST REVIEW
============================================================

Do not rely only on automated profiling.

Perform an independent analyst review of the dataset.

Look for:

- Suspicious records
- Business logic inconsistencies
- Relationships between columns that do not make sense
- Values that are technically valid but suspicious
- Potential incorrect source data
- Possible transformation risks
- Anything automated profiling may not detect

If something is suspicious but cannot be confirmed as incorrect, flag it for review instead of changing it automatically.

============================================================
7. ISSUE CLASSIFICATION
============================================================

After the complete inspection, classify every identified issue into one of these categories:

A. DEFINITELY REQUIRES CLEANING

Issues that can safely be corrected without changing business meaning.

Examples may include:

- Leading/trailing whitespace
- Empty strings converted to missing values
- Clearly inconsistent formatting
- Correctable datatype formatting

B. REQUIRES TRANSFORMATION

Changes required to prepare the dataset properly.

For each transformation, explain:

- What will change
- Why it needs to change
- The expected result
- Whether business meaning is preserved

C. REQUIRES ANALYST / BUSINESS DECISION

Issues where the correct action cannot be assumed.

Examples:

- Suspicious values
- Unexpected categories
- Missing important information
- Possible duplicates
- Conflicting records
- Unclear status values

DO NOT automatically change these.

Clearly explain the decision that needs to be made.

D. SHOULD NOT BE CHANGED

Identify values or issues that may look unusual but should remain unchanged because there is no justified reason to modify them.

## MANDATORY DATATYPE TRANSFORMATION REVIEW

During every Pre-ETL Inspection and ETL workflow, you must separately review:

1. The CURRENT source datatype.
2. The BUSINESS meaning of the column.
3. The REQUIRED clean/working dataset datatype.
4. The APPROVED target database datatype.

Do not assume that a valid value means no transformation is required.

A column may contain valid values but still require datatype transformation.

Examples:

- Valid date strings → may still require conversion to datetime.
- Numeric values stored as text → may require numeric conversion.
- Boolean values stored as text → may require boolean conversion.
- Identifier values → may need to remain text even if they contain numbers.

For every detected date, numeric, boolean, or other typed field, explicitly classify it as:

A. No transformation required
B. Datatype conversion required
C. Value cleaning required
D. Both value cleaning and datatype conversion required

- Date value validity
- Invalid dates
- Missing dates
- Mixed date formats
- Ambiguous date formats
- Future dates
- Business date relationships
- Current source datatype
- Required working/clean datatype
- Target database datatype
- Whether datatype conversion is required

IMPORTANT:

that no transformation is required.

The analyst must explicitly state whether the date column needs conversion
before the dataset can be considered transformation-ready.
